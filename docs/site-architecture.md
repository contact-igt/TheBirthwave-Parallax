## Natural Birth — route decision (resolved this pass)

**Canonical route: `/services/natural-birth`.** A prior audit confirmed no
`/natural-birth` or `/services/natural-birth` route existed anywhere in
this codebase — "Natural Birth" previously appeared only inside Dr.
Santoshi Nandigam's `specialFocus` text and one FAQ question. This pass
added a full dedicated landing page at `/services/natural-birth`,
following the exact same pattern as its 11 sibling service pages
(`services-content.ts` record, its own `natural-birth-landing-content.ts`
+ `natural-birth-landing-imagery.ts`, components under
`src/components/sections/services/natural-birth/`).

`/natural-birth` (without the `/services/` prefix) was never created —
there is no duplicate route to redirect. Positioning, deliberately kept
distinct from its closest siblings:
- **Natural Birth** — birth preferences, preparation, physiological-birth
  planning, informed choices, flexibility if circumstances change.
- **Normal Birth & Delivery Care** — labour support, the delivery-care
  pathway, practical arrangements.
- **Birth Preparation** — education and readiness before labour.
- **VBAC** — birth planning specifically after a previous caesarean.

## Navigation

Header + footer (`navigation.links`, shared): About, Our Care (→
`/services`), Doctors, Contact (→ `/#connect`, the homepage's real closing
CTA — not `/contact`, which has no confirmed content yet).

Footer adds `footer.secondaryLinks` (footer-only, added this pass): FAQ
(→ `/faq`).

## Sitemap scope

`/sitemap.xml` (`src/app/sitemap.ts`) includes: `/`, `/services`,
`/doctors`, `/about`, `/faq`, all 12 `/services/[slug]` routes (Natural
Birth included automatically — `sitemap.ts` maps over `services` from
`services-content.ts`, never a hand-typed URL list), all 10
`/doctors/[slug]` routes — 27 URLs total.

Excluded: `/contact`, `/privacy`, `/the-experience` — all three are still
"page in development" placeholders with no confirmed content (per each
route's own file comment). The routes remain live and reachable; they're
simply not being actively submitted for indexing yet. Revisit once real
content lands.

**Domain**: no production domain is confirmed anywhere in this project.
`sitemap.ts`/`robots.ts` fall back to the obviously-placeholder
`https://example.com` via `process.env.NEXT_PUBLIC_SITE_URL`. Set that
env var before relying on either file for real search-engine submission.
